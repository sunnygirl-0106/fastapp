## 2. 状态统一为「待更新」

### 2.1 规则

全产品只有一个状态：**「待更新」**。它挂在镜头上，意思是「这个镜头的成品不是最新的」。第 2 步段落列表、第 4 步镜头表、第 5 步视频页显示的是同一个状态、同一个标记。

**触发**：分两类。

| 类别 | 操作 | 标记哪些镜头 | 条件 |
|---|---|---|---|
| A 影响镜头设计 | 改段落原文（没有勾选「这次修改不影响镜头」时） | 该段的镜头 | 总是标记 |
| | 新增角色 / 场景 | 原文包含该名称的段落的镜头 | 总是标记 |
| | 删除角色 / 场景 | 引用它的镜头 | 总是标记 |
| B 只影响视频 | 改时长 | 该镜头 | 只在该镜头**已有视频**时标记 |
| | 换参考图、清除参考图 | 引用该资产的镜头 | 同上 |
| | 改镜头字段（包括画面节奏） | 该镜头 | 同上 |
| | 重新生成镜头 | 该镜头 | 同上 |
| | 改名并选择「同步替换」 | 文字被替换的镜头 | 同上 |

**不触发**：改生图提示词；改名时只更新了 @引用（第 6 节）；改标题。

**消除**：
- **视频生成成功**：清空。生成过程中又发生的改动，照旧在结果出来后补上。
- **重新生成镜头成功**：没有视频的镜头，清空；已有视频的镜头，原因换成一条「镜头已重新生成」。
- **点「保留」**：清空。
- 把时长等改回原值，不会自动消除，这条和现在一样。

### 2.2 数据

- 以 `shot.outdated`（原因列表）作为唯一的数据来源，原因要能区分 A 类和 B 类（2.3 节要用）。
- 去掉 `video.stale` / `video.staleReason`。加载旧项目时，把它们迁移成一条 B 类原因。
- 生成期间暂存原因的两套机制（`pendingShotReasons`、`pendingVideoStale`）合并成一套。

### 2.3 界面

1. **标记**：
   - 第 4 步：「视频」列的「需重新生成」和镜头上的待更新标记，合并成一个「待更新」标记，样式沿用现在的琥珀色小标签；
   - 第 5 步：视频卡片上的「需重新生成」改为同一个「待更新」标记；
   - 第 2 步：段落旁的「镜头待更新」改为「待更新」。
2. **弹出框**（点标记后出现）：
   - 标题「镜头 01 待更新」，下面列出原因；
   - 按钮依次是「保留」「✦50 重新生成镜头」「✦N 重新生成视频」。「重新生成视频」只在已有视频时出现；在第 5 步，这个按钮和现在一样，跳到第 4 步。
3. **第 4 步顶部提示条**：文案改为「N 个镜头待更新」，按钮「全部保留」。
4. **生成视频确认弹窗**：删掉「其中 N 个镜头描述待更新，仍会按旧描述生成」这条提示。
5. **默认选中**：
   - 「生成镜头设计」弹窗：没有镜头的段落 + 带 A 类原因的镜头；
   - 第 4 步「生成视频」：没有视频的镜头 + 待更新的镜头。
6. **其他文案**：所有提到「需重新生成」「保留当前描述」「保留当前视频」的地方，分别统一为「待更新」「保留」。

## 4. 画面节奏的序号

- **显示**：界面上自动显示 ①②③……（最多到 ⑳，超过 20 拍时显示「21.」），沿用现在的样式。
- **编辑**（单元格就地编辑和详情抽屉都一样）：
  - 输入框里每行一拍，**不显示序号**；
  - 保存时自动去掉每行开头的序号，包括「①」「1.」「1、」「1）」「(1)」「（1）」等写法，空行也去掉。
- **`timelineLines` 和拼接**：能去掉上面所有写法的序号。`buildVideoPrompt` 去掉 `slice(0, 8)`，用户写了多少拍就排多少拍。
- 存储格式由你决定，但界面显示、视频提示词和发给模型的「已有镜头」三处结果必须一致。

## 5. 「@名称」高亮

在所有**只读显示**镜头文字的地方，都把「@名称」显示成小标签：第 4 步表格单元格、第 5 步镜头信息，以及视频版本的提示词快照。

**样式**：
- 行内显示，不换行，圆角 4px，左右内边距 4px，字重 medium；
- 角色：`bg-brand/15`，文字 `text-brand-light`；
- 场景：`bg-violet-400/15`，文字 `text-violet-200`；
- 不用琥珀色，避免和「待更新」混淆；
- 「@」符号透明度 60%，名称正常显示。

**悬停**：弹出一个约 160px 宽的小卡片，显示参考图缩略图和「角色 · 阿哲」；没有参考图时显示「还没有参考图」。

**对不上的 @**：资产列表里找不到的「@xx」，显示为 `text-red-300` 加虚线下划线，悬停提示「找不到这个角色或场景」。

**匹配规则**：只匹配当前项目里的资产名称，较长的名称优先。比如同时有「小雨」和「小雨妈妈」，「@小雨妈妈」整体匹配为后者。

**视频提示词快照**：快照里的「@图片N」也用同样的标签样式，按它对应的资产区分角色或场景，悬停显示对应的参考图。

**编辑时**：输入框里仍是普通文字，保存后恢复标签显示。

## 6. 改名与重名

1. **@引用始终跟着更新**：改名时，**无论是否同步替换**，镜头所有字段（包括画面节奏）里的「@旧名」都改成「@新名」。替换时较长的名称优先，例如改「小雨」时不能动到「@小雨妈妈」。只更新了 @引用时，不触发待更新。
2. **同步替换弹窗**：保留现在的弹窗，但只列出**不带 @** 的出现位置。没有这类出现位置时，不弹窗，直接保存。选择「同步替换」后，按第 2 节 B 类规则触发待更新。
3. **不能重名**：改名和新增时，都要检查**全部**角色和场景，现在只检查同类型。重名时在名称输入框下面显示「名称已被其他角色或场景使用」，保存按钮置灰。
