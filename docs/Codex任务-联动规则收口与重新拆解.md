# Codex 任务：时长凑齐、重新拆解、新增角色场景、联动规则收口（v7）

> 仓库：本仓库（PhanthyMovie 全自动工作流的前端演示，纯前端 mock 加 localStorage）。只改前端演示，不接后端；所有「生成」继续走 `src/services/generation.ts` 的 mock。
> 基线：在**当前工作区代码**（包含已实现但未提交的 v4–v6）的基础上修改。**不要还原或重置工作区，完成后先不要提交。**
> mock 只负责模拟后端应该返回的结果；时长分配等规则在真实环境里由后端提示词保证，见《全自动工作流-后端提示词改动记录》。

**不能破坏的现有行为**
- 视频多版本：每生成一次就追加一个新版本，旧版本保留，新版本自动设为采用版本；失败不占版本号。
- 「确认即推进」：`start*` 系列动作先置为 generating，再切页，最后跑生成。
- 剧本在开始拆解后锁定。
- v6 的规则：改时长、直接改镜头字段，都不会让镜头进入「待更新」，只会把已有视频标为「需重新生成」。
- 第 4 步的字段显隐、筛选与定位闪动、单元格就地编辑自动保存、右侧详情抽屉。
- 「保留当前描述」的三个入口；有待更新镜头时仍然可以生成视频（弹窗里有提示）。
- 生成视频弹窗按镜头时长把不支持的模型置灰。
- 第 3 步：没有补齐全部参考图时，不能首次生成镜头设计（强制补齐，这一条不变）。
- `src/proposal/` 方案页不动。

## 0. 本轮要解决什么

1. **时长凑齐**：选择「指定时长」后，自动拆解出的各段时长加起来必须正好等于目标时长。现在选 120 秒拆出来是 30/30/30，合计只有 90 秒。
2. **重新拆解**：加回「重新拆解」入口，但只在开始提取角色与场景之前可用。
3. **取消重新提取**：去掉「重新提取角色与场景」的入口和相关提示；改为在第 3 步提供「新增角色 / 新增场景」。
4. **联动规则收口**：
   - 改「参考图描述」不再让镜头进入「待更新」；
   - 资产改名后同步替换、删除资产，都要把已有视频标为「需重新生成」；
   - 新增资产后，引用到它的镜头进入「待更新」。
5. **保留当前视频**：「需重新生成」可以像「待更新」一样由用户选择保留并消掉。
6. **改回原值不自动消提示**：时长改回原来的值后，「需重新生成」不再自动消失，和其他提示统一，由用户自己选择保留。
7. **生成过程中的改动不能丢**：镜头或视频生成期间，上游又发生了改动，结果出来后要带上对应的提示。
8. **小项**：删除镜头加二次确认；风格参考按项目保存；修正一处文案。

## 1. 时长

### 1.1 指定时长：mock 拆解必须凑齐目标（`workflowStore.ts` 的 `finishSegments`、`utils/project.ts`）

只修改指定模式；自动模式的行为保持不变（3 段，每段 `min(15, 字数 / 6)`）。

**第一步：确定段数 N**
```
N = max(ceil(T / 30), min(3, floor(T / 4)))
```
举例：T=60 → 3 段；T=120 → 4 段；T=8 → 2 段；T=4 → 1 段；T=600 → 20 段。

**第二步：生成段落**
- **N = 3**：直接用 `sampleSegments()`，保持 s1/s2/s3 不变，这样现有的 60 秒 → 27/16/17 回归用例继续成立。
- **N < 3**：把示例段落按顺序合并相邻的段（N=2：s1 一段，s2+s3 一段；N=1：全部合成一段）。
- **N > 3**：把三段示例原文连起来，先按句子切开（以 `。！？…` 断句，标点保留在句尾）。
  - 句子数量少于 N 时，再按 `，；` 往下切；还不够，就按字数硬切。
  - 切好后，把连续的小块按字数尽量均匀地分成 N 组。
  - 每组生成一个段落：`id` 用 `uid('seg')`，标题取正文前 10 个字加「…」。

**第三步：分配时长**

新增函数 `allocateExact(T, weights, min = 4, max = 30)`：
- 先按字数权重成比例分配；
- 超出 [4, 30] 的段落按边界截断，截掉或补上的差额重新分给其余没有截断的段；反复进行，直到所有段都在范围内；
- 最后按「最大余数法」取整，取整时同样不能越过 [4, 30]；
- **保证合计正好等于 T**。前面的段数公式已经保证一定分得出来。

**其他**
- 指定模式下，`allocateSegmentDurations` 的分配也改用 `allocateExact`（存量迁移补时长时会用到）。
- `finishSegments` 的 toast 改为按实际段数显示：`已生成 N 个剧本段落`（现在写死为 3）。

### 1.2 手动新增段落：由用户填时长

- 「新增剧本段落」弹窗加一个时长调节器（复用 `DurationStepper`，默认 15 秒，范围 4–30 秒）。
- `addSegment(title, text, dur)` 直接使用用户填的值，不再按剩余预算分配。
- 合计和目标不一致时，页头照常显示「目标 X 秒 · 当前合计 Y 秒」，不做额外提示。

### 1.3 改回原时长，不再自动清除「需重新生成」

- `syncDurationVideoStale` 只保留标记的一半：新时长不等于采用版本的时长时，标为「需重新生成」。删掉「改回原值时清除 stale」的分支。
- 迁移逻辑也走这个函数，行为随之改变。

## 5. 联动规则修正

修正后的完整规则如下，加粗的行是本轮新改的：

| 用户的改动 | 镜头 | 视频 |
|---|---|---|
| 段落原文 | 待更新 | — |
| 段落或镜头的时长 | — | 需重新生成 |
| 资产描述 | 待更新 | — |
| **资产参考图描述（生图提示词）** | **—（不再标记）** | — |
| 资产参考图（生成、上传、清除） | — | 需重新生成 |
| **资产改名并同步替换** | — | **文本被改动的镜头：需重新生成** |
| **删除资产** | 待更新 | **需重新生成** |
| **新增资产** | **待更新** | — |
| 镜头字段、重新生成镜头 | — | 需重新生成 |

具体改动：
- **`updateAsset`**：只有描述（`desc`）变了才标镜头「待更新」；只改参考图描述（`prompt`），不标记，toast 为 `设定已保存`。由此：
  - 「AI 生成图片」弹窗和「一键补全参考图」弹窗里改提示词，不再让镜头进入「待更新」；
  - 「编辑设定」弹窗里的「这次修改不影响已生成的 N 个镜头」勾选框，只在描述有变化时显示。
- **`renameAsset`（同步替换）**：字段确实被替换过的镜头，执行 `markVideoStale(ids, '镜头描述已修改')`。段落原文同步替换后，不标镜头「待更新」。
- **`deleteAsset`**：在现有标「待更新」的基础上，再执行 `markVideoStale(refs, '角色「X」已删除')`（场景同理）。删除确认弹窗的文案改为：`「X」被 N 个镜头引用。删除后，这些镜头会标记为待更新，已生成的视频会标记为需重新生成。`

## 7. 生成过程中又发生的改动

### 7.1 镜头生成中
- 生成期间，在内存里（模块级变量，不持久化）记两样东西：正在生成的段落 `generatingSegIds`，以及各段积压的待更新原因 `pendingShotReasons: Map<segId, OutdatedReason[]>`。
- 这几种改动会影响正在生成的段时，除了照常标记，还要把原因记进对应段：
  - 段落原文（不勾选「只改了错别字」时）；
  - 资产描述；
  - 删除资产、新增资产（段落原文或已有镜头引用了该资产）。
- `finishShots` 写回新镜头时，`outdated` 取这一段积压的原因（去重），不再一律写 `[]`。完成后清空。

### 7.2 视频生成中
- `markVideoStale` 碰到 `video.state === 'generating'` 的镜头时，不管有没有旧版本，都把原因记进 `pendingVideoStale: Map<shotId, string>`（以最后一次为准）。
- 时长在生成期间被改，也同样记下（原因：`时长改为 X 秒`）。
- `finishVideos` 写入新版本后：有积压原因，就标 `stale = true` 并写入原因；没有，就照常清除。
