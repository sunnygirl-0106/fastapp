## 1. 密钥与调用

### 1.1 密钥
- 用户会把 OpenRouter 密钥发给你。写进仓库根目录的 `.env.local`：
  ```
  OPENROUTER_API_KEY=用户给的密钥
  OPENROUTER_MODEL=google/gemini-3.1-pro-preview
  ```
- 确认 `.gitignore` 已经忽略 `*.local`（现在已经有这一条）。
- **密钥只能留在 Vite 开发服务器上**：
  - 变量名不能加 `VITE_` 前缀；
  - 不能出现在浏览器代码、构建产物、日志、检查脚本输出或任何文档里。

### 1.2 代理
在 `vite.config.ts` 里：
- 用 `loadEnv(mode, process.cwd(), '')` 读取上面两个变量，以及第 1.4 节的预算变量。
- 不用 Vite 自带的 `server.proxy`，改写一个只在开发模式生效的小插件（`configureServer` 加中间件），接管 `POST /api/openrouter/chat/completions`：
  1. 先做第 1.4 节的预算检查，超出就直接拒绝，不转发；
  2. 带上 `Authorization: Bearer <密钥>` 请求头，转发到 `https://openrouter.ai/api/v1/chat/completions`。浏览器端不带密钥；
  3. 拿到响应后记一条费用记录（第 1.4 节），再把响应原样返回给浏览器。
- 用 `define` 暴露两个**不含密钥**的常量：
  - `__REAL_TEXT__`：开发模式（`command === 'serve'`）、密钥存在、并且环境变量 `PHANTHY_MOCK` 没有设置时为 `true`，其他情况一律为 `false`；
  - `__TEXT_MODEL__`：模型名。
- 在 `vite-env.d.ts` 里声明这两个常量的类型。

### 1.3 调用函数
新建 `src/services/textModel.ts`，导出 `callText(system, user)`：
- `POST /api/openrouter/chat/completions`，请求体为：
  ```
  { model: __TEXT_MODEL__, messages: [{role:'system', content: system}, {role:'user', content: user}], usage: { include: true } }
  ```
- 超时 300 秒；网络层不自动重试。
- 返回 `{ text, usage }`。在控制台打一行日志：哪一步、输入 / 输出 / 思考 token 数、费用（美元）。
- 弹窗里的「文本模型」下拉框保持原样；真实调用一律用 `__TEXT_MODEL__`。
- 请求头里带上 `X-Phanthy-Step`（取值：拆解剧本 / 提取角色与场景 / 生成镜头设计），供费用记录使用。

### 1.4 费用记录与预算上限（重要：用户总共只有 5 美元）
**预算变量**：写进 `.env.local`，下面是默认值：
```
BUDGET_USD=5
STOP_AT_USD=4.5
```
`STOP_AT_USD` 比总额少 0.5 美元，留作余量，因为一次镜头调用可能花掉 0.1–0.3 美元。

**记录**：
- 每次真实调用结束后（包括失败和自动重试），在仓库根目录的 `.usage/usage.jsonl` 追加一行，内容为：
  - 时间、步骤、模型；
  - 输入、输出、思考 token 数；
  - 费用（取响应里的 `usage.cost`，单位美元）；
  - 是否成功、耗时。
- 没返回费用的调用记为「未知」，不要当成 0。
- `.usage/` 加进 `.gitignore`。

**已花金额**：每次调用前，后端按下面的方法确定已花金额：
- 请求 `GET https://openrouter.ai/api/v1/key`（同样带密钥），取返回里的 `usage`。这是这把密钥在 OpenRouter 上的真实累计花费，测试面板等其他地方用同一把密钥的花费也会算进去；
- 这个接口请求失败时，退回用 `.usage/usage.jsonl` 的本地合计；
- 两个数都拿得到时，取较大的那个。

**拦截**：已花金额 ≥ `STOP_AT_USD` 时：
- 中间件不再转发，直接返回 HTTP 402，提示「预算已用到 $X / $5，已停止调用」；
- 前端按调用失败处理（第 6 节），toast 显示这句提示，并且不再自动重试。

**两轮真实验收的上限**（第 8 节第 4 步）：
- 每轮开始前，先在 `/usage` 记下当前已花金额 A，再把 `STOP_AT_USD` 临时设为 A + 0.5，重启开发服务器后再跑。这样单轮最多花 0.5 美元，超过就自动拦截。
- 两轮合计不得超过 1 美元。
- 任何一轮被拦截，或者两轮合计接近 1 美元时，立即停下并报告，不要调高上限继续跑。
- 两轮都跑完后，把 `STOP_AT_USD` 改回 4.5。

**查看网页**：开发模式下，浏览器打开 `http://localhost:5188/usage` 能看到一个简单的中文页面：
- **顶部三个数字**：已花多少（OpenRouter 实际数和本地记录数都列出）、还剩多少（以 5 美元计）、离自动停止还有多少；
- **下面一张表**：每次调用的时间、步骤、token 数、费用、是否成功，最新的排在最上面；
- 每 5 秒自动刷新。
- 页面由同一个中间件直接返回 HTML，不放进 React 应用，也不需要登录。

**页面角标**：开发模式、并且是真实模式时，应用右下角显示一个很小的角标「已花 $0.42 / $5」：
- 点击打开 `/usage`；
- 每次调用后更新；
- 已花超过 4 美元时变成红色。
- 这是开发调试用的，`npm run build` 出来的版本里不能有这个角标。

## 3. 三次调用

总原则：
- 按《提示词文档》对应一节的「用户消息」填空、调用、解析，再执行该节「后端处理」里的每一条。
- 「自动重试 1 次」指的是：解析或校验失败时，用同样的输入再调用一次；还失败就走第 6 节的失败处理。
- 真实模式和 mock 模式走**同一套**解析和校验，只是文本来源不同。

### 3.1 拆解剧本（`finishSegments`）
- **发送前**：剧本先经过 `clean_script` 处理（去掉 Markdown 排版符号）。
- **校验**：照搬 `validate_segments`，包括原文拼接后必须等于剧本的结尾部分。
- **合计时长**：manual 模式合计不等于目标时，用 `fix_total` 修正，不重试。
- **剧本设定**：段落之前没有被覆盖的开头部分（`split_preface`），存为新字段 `project.scriptPreface`，随项目一起保存。重新拆解时覆盖。
- 段落 id 规则不变。

### 3.2 提取角色与场景（`finishAssets`）
- **用户消息**：「剧本设定」取 `project.scriptPreface`；「风格参考」取 `project.config.shotStyle`。
- **校验**：照搬 `validate_assets`，包括所有名称不能重复（角色和场景之间也不能重名），以及每个段落至少属于一个场景。
- **资产 id**：用 `uid('char')` / `uid('scene')` 生成，不用模型给的 client_key。
- 「保留同名资产已生成的参考图」照旧。
- toast 里的数量改成实际数量（现在写死成「2 个角色、1 个场景」）。

### 3.3 生成镜头设计（`finishShots`）
- **用户消息**：
  - 每段写成 `[段号] 标题（时长秒）：原文`，时长取用户在「生成镜头设计」弹窗里确认后的时长；
  - 资产列表用 `Asset.id` 作为 asset_id；
  - 重新生成时，「已有镜头」放当前字段（包括用户手改过的内容，用现有的 `encodeShot`）；
  - 「相邻段落的已有镜头」：本次范围之外、但和本次段落前后相邻、并且已经有镜头的段，只读传入；没有就省略这一部分。参考 `shot_user`。
- **分批**：一次最多 6 段，多于 6 段时按段号顺序依次调用；后一批要把前一批最后一段的镜头作为相邻镜头传入。某一批失败，不影响其他批。
- **校验**：照搬 `validate_shots`。
  - 画面描述里所有 @名称都必须能在资产列表里找到，并且至少有一个场景；
  - `asset_ids` 一律按画面描述中 @名称第一次出现的顺序重新生成（`mentions`）；
  - 拍数和建议不一致时，只在控制台提示。
- **timeline**：模型输出的数组转成现有的 `Shot.timeline` 字符串（每行一拍，用现有的 `formatTimeline`），最多 8 拍。
- **`beginShots`**：现在它会同步调用 `mockShots` 预估每段引用了哪些资产，供生成期间的联动使用。真实模式下没法预先知道，改为：预估引用的资产 = `belongSegs` 包含该段的资产 + 该段已有镜头的 `assetIds`。

## 6. 调用失败（最小处理）

完整的失败设计（`docs/生成失败-设计说明.md`）不在本轮范围。本轮只保证失败时不丢内容、不乱扣费、能重试：

| 步骤 | 失败后 |
|---|---|
| 首次拆解 | `segStatus` 回到 `none`，回到第 1 步，剧本原样保留 |
| 重新拆解 | 保留原来的段落，`segStatus` 回到 `done`，停在第 2 步 |
| 提取角色与场景 | `assetStatus` 回到 `none`，停在第 2 步 |
| 生成镜头 | 成功的段照常更新；失败的段：原来有镜头的保留原镜头，原来没有的不新增；`shotStatus` 有镜头时为 `done`，否则回到 `none` |

- **扣费**：只在成功时扣，镜头只按成功的段数扣。
- **toast**：写明失败原因和「本次未扣费」，例如「拆解失败：模型返回格式错误，本次未扣费」「2 个段落生成失败，本次未扣费」。
- **清理**：`generatingAssetIds`、`generatingSegIds`、`pendingShotReasons` 等生成期间的临时状态，在 `finally` 里清理，失败时也要清理。

- mock 输出必须能通过第 3 节的同一套校验。具体来说：
  - mock 镜头的画面描述里，用「@名称」写出引用的场景和角色；
  - mock 资产要覆盖所有段落。
- **检查脚本**：
  - `scripts/check-workflow.mjs` 启动前设置 `process.env.PHANTHY_MOCK = '1'`，保证即使存在 `.env.local` 也不会真实调用；
  - 原有断言按本文档更新后全部通过，并新增以下断言：
    - 时间轴：同一镜头在 4 / 15 / 30 秒下，首尾时间正确、相邻时间段首尾相接，有台词的拍分到的时间更多；
    - @ 替换：较长名称优先，比如「小雨妈妈」不会被「小雨」误替换；
    - `fix_total` 修正后合计等于目标，每段在 4–30 秒内；
    - 剧本设定能被识别并存进 `scriptPreface`；
    - 风格参考在第 1 步填写后出现在第 2、3 步的用户消息里，`GenShotModal` 里没有文本框；
    - 构建产物 `dist/` 和源码里都搜不到密钥。
