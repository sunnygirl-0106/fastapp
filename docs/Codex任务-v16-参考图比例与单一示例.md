## 3. 示意占位图

新建 `src/data/refPlaceholders.ts`，导出 `refPlaceholder(kind: 'char' | 'scene', ratio: string, name: string): string`，返回 `data:image/svg+xml` 地址。SVG 要带真实的 `width` / `height`，让大图能按原比例显示：16:9 为 1600×900，9:16 为 900×1600，1:1 为 1200×1200，4:3 为 1200×900，3:4 为 900×1200。

画面要求（简单几何图形即可，深色底、低饱和色，不要文字以外的细节）：
- **角色 16:9**：左侧 40% 画一个头肩特写（圆形头 + 肩线），右侧 60% 并排画三个全身剪影，下方分别标「正面」「侧面」「背面」。对应模板 A 的三视图版式。
- **角色其他比例**：居中画一个全身剪影。
- **场景 16:9**：2×2 四宫格，每格画一个简单的房间透视（地面线 + 后墙 + 门窗），四格分别标「1 正面」「2 左前 45°」「3 右前 45°」「4 反向」。对应模板 B 的四视图版式。
- **场景其他比例**：画一个房间透视。
- **每张图**：左上角标名称，右下角标比例（如「16:9」）。

`mockImage` 只继续用于视频封面。参考图（生成、预置项目）一律改用 `refPlaceholder`。

## 6. 同步提示词文档（11-07、11-08 改动）

演示代码按占位符原文和字段名读取提示词文档。下面这些改动不同步，mock 流程会报错或拼出错误的提示词：

**风格**
- 第一节（拆解）用户消息新增「风格参考：{用户填写的内容，可以为空}」一行，填用户在拆解弹窗里填的风格（现在存在 `config.shotStyle`）。
- 拆解输出的 meta 只剩 `{"type":"meta","style":"…"}`。要把它保存到项目上（例如 `project.style`），这是整部剧唯一的风格。mock 拆解要输出 style：载入示例时用 fixture 的 `style`；其他情况下，用户填了就用用户填的，没填就用「写实电影风格」。
- 第二、三节用户消息里的占位符改成了「风格参考：{拆解生成的风格}」，填 `project.style`。
- 模板 A、B、C 里的 `{风格参考}` 也都填 `project.style`，不再用 `config.shotStyle`。模板 C 去掉了「为空时写写实电影风格」。

**字段删除**
- 拆解 meta：删了 `duration_mode`、`total_seconds`。
- 提取：asset 只剩 `type`、`kind`、`name`、`prompt`，删了 `client_key`、`importance`、`segment_ordinals`（`alias` 之前就删了）。`validation.ts` 和 `parse.ts` 里对应的校验、编码一起删。`belongSegs` 改成由程序计算：角色按名称在段落原文里匹配，场景按镜头里的 @引用。
- 镜头：删了 `asset_ids`。镜头引用了哪些角色和场景，一律从画面描述（`shot` 字段）里「@名称」第一次出现的顺序解析（`validation.ts` 约 216 行已经有推导逻辑，改成唯一来源）。
- 第三节用户消息的角色与场景行，从「{asset_id}｜{角色 / 场景}｜{name}｜{prompt}」改成了「{角色 / 场景}｜{name}｜{prompt}」。`prompts.ts` 约 78 行现在用 `{asset_id}` 判断这一行，要改成用 `{角色 / 场景}` 判断。
- 第二节用户消息删除了「剧本设定」两行，`{剧本设定}` 和 `scriptPreface` 不再使用。
- 项目封面兜底（`utils/project.ts` 约 90 行）里的「主要角色参考图」改成「第一张角色参考图」。

**模板**
- 模板 A：「画面风格：{风格参考}」移到了第一行。
- 模板 B：换成了四视图后缀，结构是「{prompt}。……后缀……」加最后一行「[视觉风格：{风格参考}]」，不再有 `{name}`。

改完后，用当前的提示词文档跑一遍完整五步 mock 流程，**控制台不能有提示词解析错误**。
