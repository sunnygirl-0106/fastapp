## 0. 本轮要解决什么

v5 把「时间安排」改成了不写秒数的「画面节奏」，镜头内容已经不依赖时长。但现在改时长仍然会让镜头进入「待更新」、弹「时长改为 X 秒」小卡片、提示重新生成镜头，这条规则已经没有依据了。

本轮改为：**时长是视频参数，改了立即生效，不影响镜头描述。** 只有已经生成过视频的镜头，视频标「需重新生成」（和换参考图一样）。

同理，第 4 步**直接改镜头字段**（表格就地编辑、详情抽屉）也不再让镜头进入「待更新」——用户改的就是镜头本身，只把已有视频标「需重新生成」。

改完后只剩两种标记，规则一句话：**镜头「待更新」看上游（段落原文、角色与场景）有没有变；视频「需重新生成」看镜头本身（描述、时长、参考图、重新生成）有没有变。**

## 1. 数据规则（`workflowStore.ts`）

### 1.1 改时长 = 同时改段落和镜头

`updateSegment(id, { dur })` 改为：
- 写 `seg.dur`；如果这个段落有镜头，**同时写 `shot.dur`**（两者从此始终相等）。
- **不再**调用 `markOutdated(..., { kind: 'segDur' })`，也不再按时长清除待更新原因。
- 如果镜头已有视频（`video.versions.length > 0`）：
  - 新时长 ≠ 采用版本的时长 → `markVideoStale(p, [shot.id], '时长改为 X 秒')`；
  - 新时长 = 采用版本的时长，且当前 `staleReason` 是 `时长改为…` → 清除 `stale` 和 `staleReason`（改回去就当没改过）。其他原因造成的 stale 不动。
- **只改时长时不弹 toast**（数字本身就是反馈）。改原文的 toast 不变。

### 1.2 删掉 `segDur` 相关逻辑

- `types.ts`：`OutdatedKind` 去掉 `'segDur'`。
- `retainShotDescription`：去掉「把时长改回原值」的分支，只清空 `outdated`；`dismissOutdated` 的 toast 固定为 `已保留当前描述`（去掉「，时长恢复为 X 秒」）。
- `migrateProjects`：
  - 删掉现在对 `segDur` 原因改写文案的那一行；
  - 所有镜头的 `outdated` 里去掉 `kind === 'segDur'` 的原因；
  - 段落和镜头时长不一致的（存量里改了时长还没重新生成的），**以段落时长为准**：`shot.dur = seg.dur`，并按 1.1 的规则标视频 stale。

### 1.3 直接改镜头字段：只标视频，不标待更新

- `updateShot`：删掉对每个改动字段调用 `markOutdated(p, [id], { kind: 'shotEdit', … })` 的循环；保留「值真的变化才写入」的判断，以及已有视频时 `markVideoStale(p, [id], '镜头描述已修改')`。
- 镜头原本已有的待更新原因（来自上游）**保持不变**，编辑字段既不新增、也不清除原因。
- `types.ts`：`OutdatedKind` 去掉 `'shotEdit'`，只剩 `'segText' | 'asset'`；`markOutdated` 里按 `key` 去重的条件相应简化为只看 `asset`。
- `migrateProjects`：所有镜头的 `outdated` 里去掉 `kind === 'shotEdit'` 的原因（只有这类原因的镜头随之不再待更新）。
- 重新生成镜头时把用户当前的手动修改作为输入：不变（字段里存的就是用户改过的内容）。

### 1.4 生成镜头弹窗、重新生成镜头

- `startShots` / `finishShots` 写回时长的逻辑不变（弹窗里改的时长随生成一起写入，已和 1.1 一致）。
- `regenerateShot` 用当前 `shot.dur`，不变。

## 3. 本轮不改

- 「待更新」的其余触发（本轮之后只剩这四种）：段落原文修改、角色或场景设定修改、角色或场景删除、重新提取角色与场景。
- 视频「需重新生成」的其余触发：镜头重新生成、引用的角色或场景换了参考图。
- 第 4 步提示条文案「…的上游内容有修改。如果只是改错别字这类不影响画面的修改，可以保留当前描述。」不变（现在它说的就是上游）。
- 「保留当前描述」的三个入口（编辑时勾选「只改了错别字」、提示条「全部保留当前描述」、每个镜头的「待更新」小标签）。
- 重新生成镜头 = 完全重写，带上用户当前的手动修改。
- 有待更新镜头时仍可生成视频，弹窗提示「其中 N 个镜头描述待更新…仍会按旧描述生成」。
- 视频生成弹窗的模型置灰规则（按 `shot.dur` 判断，现在它总等于段落时长）、价格。

## 4. 验收清单

4. 给镜头 01 生成视频（v1，20 秒），再把时长改为 24 → 视频状态变为 `需重新生成`，`staleReason === '时长改为 24 秒'`；镜头描述不变、没有「待更新」。

6. 镜头 01 换了引用角色的参考图（stale 原因是「角色「苏可」参考图已更新」）后再改时长并改回 → 仍是 `需重新生成`（非时长原因不被清除）。
7. 接第 4 条，打开生成视频弹窗 → 镜头 01 按 24 秒计价、计时长；第 5 步卡片显示 `· 需重新生成`，没有「可重新生成」字样。
