## 2. A · 任意时长

### 2.1 规则

- 时长为整数秒，范围 **4–15 秒**（默认视频模型 Seedance 2.0 的能力范围）。
- 一个段落对应一个镜头，对应一条视频。
- 三个时长各有含义，不要混用：
  - `segment.dur`：目标时长。用户在第 2 步或第 4 步改的都是它。生成或重新生成镜头时，按它来写镜头描述。
  - `shot.dur`：当前镜头描述实际按多少秒编写。只在生成或重新生成镜头时，被写成 `segment.dur`。
  - `version.dur`：这一版视频的时长。生成视频时取 `shot.dur`。
- 用户改了 `segment.dur` 但还没重新生成镜头时，镜头进入「待更新」。此时如果仍然生成视频，**按旧描述和旧时长（shot.dur）生成**，保证画面描述和时长一致。

### 2.2 「时间安排」的分槽规则（镜头设计的产出规则，mock 也按它来）

导演逻辑：一个时间槽是一个"节拍"，即一个动作或一次情绪变化；5 秒以内只放一个节拍。

- 槽数 `n = ceil(dur / 5)`，分界点依次为 5 秒、10 秒，最后一槽结束于 `dur`。
- 最后一槽不足 2 秒时，并入上一槽（避免出现无法表演的 1 秒槽）。
- 由于上限是 15 秒，槽数只会是 1、2 或 3。

| 时长 | 时间槽 |
|---|---|
| 4 | 0–4秒 |
| 5 | 0–5秒 |
| 6 | 0–6秒（5–6 只有 1 秒，并入） |
| 7 | 0–5秒 / 5–7秒 |
| 10 | 0–5秒 / 5–10秒 |
| 11 | 0–5秒 / 5–11秒 |
| 12 | 0–5秒 / 5–10秒 / 10–12秒 |
| 15 | 0–5秒 / 5–10秒 / 10–15秒 |

在 `src/utils/project.ts` 里新增：
- `timeSlots(dur): [number, number][]`：按上面的规则返回各槽的起止秒。
- `buildTimeline(beats: string[], dur): string`（mock 用）：
  1. 把原 timeline 每行去掉「0–5秒：」这类前缀，得到节拍文本 `beats`；
  2. 按 `timeSlots(dur)` 排进槽里，槽不够时，多出的节拍用「；」接到最后一槽；
  3. 每行输出成 `起–止秒：节拍`，行与行之间用 `\n` 分隔。

### 2.3 通用组件 `DurationChip`（新建 `src/components/DurationChip.tsx`）

- **常态**：文字「15 秒」，样式沿用现有的时长文字（`text-white/40`、12–14px）。hover 时出现 1px 虚线下划线，指针变为可点。

  - 下方说明「4–15 秒，整数」，颜色 `text-faint`。

### 3.2 改动传播规则（核心，按此实现）

**"引用"的判定**：一个镜头引用某个资产，满足任意一条即可：
1. 资产名出现在该镜头任一文本字段里；
2. 资产名出现在该镜头对应段落的原文里；
3. 资产是场景，且它的 `belongSegs` 包含该段落的 `no`。

实现为 `shotsReferencingAsset(project, asset): Shot[]`，放在 `utils/project.ts`。

| 用户操作 | 立即效果 | 下游标记 | 用户看到的提示 |
|---|---|---|---|
| 改段落正文 | 保存 | 对应镜头加 `segText`：「段落原文已修改」；`assetsHint=true` | toast：「已保存，镜头 02 需要更新」（没有对应镜头时只提示「已保存」） |
| 改段落时长 | 保存 | `segment.dur ≠ shot.dur` 时加 `segDur`：「时长已改为 12 秒，当前描述按 15 秒编写」；改回与 `shot.dur` 相等时**移除**这条原因 | 同上 |
| 改段落标题 | 保存 | 无 | 无 |
| 新增段落 | 新段落没有对应镜头 | — | 第 4 步出现「尚未生成镜头」提示（3.4） |
| 删除段落 | 段落、对应镜头及其所有视频版本一起删除，镜头重新编号 | — | 二次确认（3.5） |
| 改角色或场景的描述、参考图描述 | 保存 | 所有引用它的镜头加 `asset`（key=资产 id）：「角色「苏可」设定已修改」 | toast：「设定已保存，3 个镜头需要更新」 |
| 生成、重新生成、上传、清除参考图 | 更新图片 | 引用它、且视频已完成的镜头：`video.stale=true`，`staleReason`：「角色「苏可」参考图已更新」。镜头描述**不**标待更新 | 无额外提示 |
| 资产改名 | 见 3.6 同步替换弹窗 | 无（文字已同步，画面没变） | — |
| 删除角色或场景 | 删除 | 引用它的镜头加 `asset`：「角色「苏可」已删除」 | 二次确认（3.6） |
| 重新提取角色与场景 | 列表重建，同名资产沿用参考图（现有逻辑）；`assetsHint=false` | 所有镜头加 `asset`（key='reextract'）：「角色与场景已重新提取」 | 确认弹窗文案见 3.6 |
| 改镜头字段（第 4 步） | 现有逻辑：视频 `stale=true` | `staleReason`：「镜头描述已修改」 | 现有 |
| 生成或重新生成镜头 | 清空 `outdated`；`shot.dur=segment.dur` | 视频 `stale=true`，`staleReason`：「镜头已重新生成」（现有逻辑补上原因） | 现有 |

**去重**：同一个镜头上，同一 `kind`（asset 类为同一 `kind+key`）只保留一条，新的覆盖旧的。

**必须同时修复的现有 bug**：`finishShots(segNos)` 目前用 `p.shots = all.filter(segNos)` 整体替换，只重新生成部分段落时，**其他段落的镜头会被删掉**。改为**合并**：只更新或新增所选段落对应的镜头（按 `segId` 匹配），其余镜头保持不动；最后按段落顺序排序并重新编号。

- **页头按钮**：待更新镜头数 > 0 时，在「重新生成镜头」左边加一个琥珀色描边胶囊按钮「更新 {N} 个待更新镜头」。点击后打开 `GenShotModal`，默认只勾选这些镜头对应的段落。

- **GenShotModal 增加「状态」列**（放在时长列之前）：
  - 未生成：`text-faint`；
  - 待更新：`text-amber-300`；
  - 已生成：`text-brand`。
  - 默认勾选：调用方传入时按传入的来；不传时，有「未生成或待更新」的段落就只勾选它们，否则全选。
  - 删除弹窗里的锁定提示。
- **视频确认弹窗的待更新提示**：所选镜头里有待更新的镜头时，在明细面板上方显示琥珀色提示块（样式同 `NoticeBar`，不带按钮）：
  - 「其中 {N} 个镜头描述待更新（镜头 02、镜头 04），仍会按旧描述生成。」
  - 超过 3 个时写「镜头 02、镜头 04 等 5 个」。
  - 确认按钮照常可点，文案不变。
- **步骤条提示点**：在菱形节点右上角加一个 6px 的琥珀色圆点（`bg-amber-400`，带 1.5px 深色描边），节点按钮的 `title` 写原因：

## 5. 实现注意

- **store 新增或修改的方法**：`updateSegment`、`deleteSegment`（级联删除镜头）、`dismissOutdated(shotId)`、`renameAsset(id, name, sync: boolean)`、`deleteAsset`（加传播）、`updateAsset`（只有 `desc` 或 `prompt` 真的变了才传播）、`generateAssetImages` 和 `clearAssetImage`（加视频 stale 传播）、`finishShots`（改为合并，并修复 3.2 提到的 bug）、`regenerateShot`、`finishSegments`（写段落 `dur`）。删除 `generateSegments` 在第 2 步的重新拆解调用路径（`startSegments` 首次拆解保留）。

## 6. 验收清单

**时长**
1. 新建项目，拆解时把单段时长设为 8 秒 → 第 2 步每段显示「8 秒」，页头总时长 = 段数 × 8。

3. 重新生成镜头 01 → 时间安排变为 3 行（0–5 / 5–10 / 10–12秒），「描述按…编写」那行小字消失，旧视频显示「需重新生成」。
